# v1.1.4 security validation

## Scope and dependency ownership

Remediates [Dependabot alert #1](https://github.com/edwynmoss/clear-rows/security/dependabot/1),
[RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html).
The change belongs to dependency integration and release infrastructure. No
application behavior or architecture is changed; no design pattern is needed.

| Owner | Writers | Consumers | Validation |
| --- | --- | --- | --- |
| Published GLib 0.18.5 source plus upstream two-line fix | Explicit changes to `src-tauri/vendor/glib`; provenance in its parent README | Linux GTK3 stack used by Tauri 2 | Optimized upstream iterator tests against real Linux GLib |
| Root Cargo patch and application lockfile | Cargo dependency resolution | All application GLib consumers | Metadata check requires one GLib package, sourced from the local patch |
| Standalone GLib test lockfile | Deliberate test dependency updates | Reusable Linux security workflow | Tests run with `--locked --release` |
| Application version and release notes | Release preparation | Desktop version, installers, updater manifest | Version alignment and release artifact checks |

GLib 0.20 contains the fix but cannot satisfy the GTK3 stack's 0.18 requirement.
Upstream has declined further 0.18 releases. The bounded solution retains the
published source and MIT license, applies the upstream fix, and preserves the
honest crate version. There is no advisory suppression or unrelated dependency
upgrade. Maintenance and removal conditions are documented in
`src-tauri/vendor/README.md`.

## Reproduction and fix

Validated on 16 September 2026 in a disposable Linux container using
`rust:1.94-slim-bookworm`, Debian's real `libglib2.0-dev` and `pkg-config`:

- The unmodified published crate's optimized iterator tests crashed with SIGSEGV.
- With only the upstream pointer mutability fix applied, all 11 iterator tests
  passed with `--locked --release --lib variant_iter`.
- All 121 published crate files were compared with the registry source. Only
  the two expected lines in `src/variant_iter.rs` differ. The standalone test
  lockfile is an intentional addition.
- The published archive SHA-256 matches the original application lockfile.
- The application metadata check resolves exactly one GLib package, from the
  patched local source. Both CI and release workflows run this check and the
  optimized tests; installer builds depend on their success.

## Application validation and review

- `npm test`: 44 frontend tests passed.
- `npx tsc --noEmit -p tsconfig.json`: passed.
- `npm run test:rust`: 81 passed; three opt-in tests ignored.
- `npm run e2e`: all four scenarios passed against the real Windows desktop app
  at version 1.1.4. Coverage includes filter scrolling, empty results, invalid
  queries, sorting, compressed files, header detection, column inspection,
  cross-file search and export. The filtered-results screenshot was inspected.
- Actionlint 1.7.12 passed for CI, release and the reusable security workflow.
- Dependency trees confirm GLib is absent from the Windows and macOS targets.
- Source and lockfile review found only the intended patch, release metadata and
  validation infrastructure changes. Application dependency versions are unchanged.

The disposable Linux container and its task-specific image were removed. Native
test processes stopped and ports 1420/9222 were checked. Synthetic fixtures,
exports and screenshots are removed after review; existing ignored build caches
are retained.

## Release boundary

Hosted CI, platform release builds, signed artifacts and public updater metadata
must pass before publication. A source backport does not guarantee that
version-only scanners will automatically close the alert; provider state is
checked separately.

Full Linux/macOS desktop UI operation and upgrading an existing installation are
not established by the isolated library regression test.
