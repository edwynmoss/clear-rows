# v1.1.3 validation

Validated on Windows on 16 September 2026 for [issue #2](https://github.com/edwynmoss/clear-rows/issues/2).

## Scope and ownership

The Rust filter mask remains authoritative for matching rows. `CsvSession.activeFilter`
mirrors the completed query and matched count. The grid owns viewport position and
cached row windows; scroll position does not change the filter or its results.

| Surface | Existing path | Change or verification |
| --- | --- | --- |
| Typed queries, builder, recent filters, cell and column actions | `applyFilter` -> `pollFilter` | A successful filter requests the first result; no reset on validation failure. |
| Grid and row fetches | Session projection -> virtualizer -> `get_csv_rows` | Uses the matched count for fetch bounds; resets vertical position and highlight; retains horizontal position for scrollable results and does not move focus. |
| No matches | Completed filter with zero matched rows | Clears rows, spacers and the stale/loading marker without fetching a phantom row. |
| Sorting and clearing | Existing grid refresh call | Preserves the existing viewport policy. |
| Column statistics | Existing `refreshColumnPanel` | Native smoke scenario verifies counts and filtering by a value. |
| Search and export | Existing Rust commands | Native smoke scenario exercises cross-file search and export. No changes to these paths. |

No backend, persistence, dependency or architecture changes. Version metadata is
updated consistently to 1.1.3. No Gang of Four pattern was introduced; the existing
filter completion path explicitly requests a grid scroll policy.

## Evidence

- Before the fix, three new frontend cases failed because the vertical offset
  remained 559,720 pixels after filtering.
- Before the fix, the native Ctrl+F/Enter scenario failed: the resulting offset
  was 53,123 pixels instead of zero.
- `npm test`: 44 tests passed across seven files. Cases include one match,
  reduced results, unchanged result count, zero matches, focus, horizontal
  position, highlight clearing and preserving the viewport on ordinary refreshes.
- `npx tsc --noEmit`: passed.
- `npm run test:rust`: 81 passed, three opt-in performance/fixture tests ignored.
  This ran before the version-only metadata bump; Rust implementation is unchanged.
- `npm run e2e`: all four scenarios passed against the real Windows desktop app
  and Rust engine using the harness's synthetic 20,000-row file. The new scenario
  covers Ctrl+F/Enter from the bottom, replacing filters, zero matches, recovery,
  invalid queries, filtering a sorted view and clearing.
- The issue scenario passed again after the 1.1.3 version bump and Windows
  harness shutdown fix. The app and ports 1420/9222 were checked after shutdown.
- `npm run tauri build`: production frontend, Windows executable, NSIS installer,
  MSI installer and both updater signatures built successfully.
- Both installer signatures were independently verified with `minisign-verify`
  against the public key configured in `tauri.conf.json`.
- The production executable was launched with the synthetic file. A UI-only
  Ctrl+F/Enter smoke check passed for filtering from the bottom, zero matches and
  clearing. The displayed version was 1.1.3 and development hooks were absent.
- Screenshots of the development and production results were visually inspected.
- The final source diff was reviewed; no new dependencies or unrelated formatting
  changes were introduced. Lockfile changes contain only the package version.

The Windows harness now waits for process termination before exiting; its previous
asynchronous cleanup left the app and development server running after a passed run.

## Release boundary

Local implementation and Windows validation are complete. Publication, installer
installation, updating an existing installed copy, and macOS/Linux runtime behavior
have not been verified. The existing tag workflow builds all three platforms and
creates a draft release; publishing that draft enables update offers.

Temporary synthetic fixtures, screenshots and verification helpers are removed
after validation. The local production executable, installers and signatures are
retained under the existing ignored build directories for release review.
